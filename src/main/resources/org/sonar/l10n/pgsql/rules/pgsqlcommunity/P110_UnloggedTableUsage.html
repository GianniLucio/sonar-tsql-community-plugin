UNLOGGED tables are not crash-safe and lose data in the event of a server crash or shutdown.

  • Durability: Data is not written to the write-ahead log (WAL)
  • Performance: Faster writes but unreliable
  • Use Cases: Only suitable for temporary, non-critical data
  • Risk: Complete data loss on unscheduled shutdown

Recommendation: Use UNLOGGED tables only for temporary working tables, not for permanent data.

Noncompliant Code:

CREATE UNLOGGED TABLE production_data (
  id SERIAL PRIMARY KEY,
  customer_id INT,
  order_amount DECIMAL
);

Compliant Code:

-- For temporary data only:
CREATE UNLOGGED TABLE temp_staging (
  id SERIAL PRIMARY KEY,
  raw_data TEXT
);

-- For production data:
CREATE TABLE production_data (
  id SERIAL PRIMARY KEY,
  customer_id INT,
  order_amount DECIMAL
);
