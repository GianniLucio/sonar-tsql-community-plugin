The SERIAL data type has several limitations and is considered legacy in PostgreSQL.

  • Compatibility: GENERATED ALWAYS AS IDENTITY is SQL standard (SQL:2016)
  • Ownership: SERIAL creates a separate sequence; GENERATED owns it automatically
  • Control: GENERATED provides better control over sequence behavior
  • Best Practice: PostgreSQL 10+ recommends GENERATED for new code

Recommendation: Use GENERATED ALWAYS AS IDENTITY or explicit GENERATED BY DEFAULT.

Noncompliant Code:

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100)
);

Compliant Code:

CREATE TABLE users (
  id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(100)
);
-- Or:
CREATE TABLE users (
  id BIGSERIAL PRIMARY KEY,
  name VARCHAR(100)
) USING GENERATED ALWAYS AS IDENTITY;
