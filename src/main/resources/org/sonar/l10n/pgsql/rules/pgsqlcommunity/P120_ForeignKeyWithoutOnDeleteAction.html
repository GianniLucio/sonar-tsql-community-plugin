Foreign key constraints should declare an explicit ON DELETE action.

When ON DELETE is omitted, PostgreSQL defaults to NO ACTION: deleting a referenced row fails with a foreign key violation unless the application anticipated it. Declaring CASCADE, SET NULL, or explicitly keeping the default makes the intended referential behavior clear.

Noncompliant Code Example

CREATE TABLE orders (
    id INT,
    user_id INT,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

Compliant Solution

CREATE TABLE orders (
    id INT,
    user_id INT,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
