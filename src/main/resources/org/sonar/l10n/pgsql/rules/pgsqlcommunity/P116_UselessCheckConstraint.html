Why is this an issue?

A CHECK constraint that always evaluates to a constant true value (such as CHECK (TRUE) or CHECK (1 = 1)) never rejects any row. It gives a false sense of data validation while adding overhead to every insert and update.

Noncompliant Code Example

CREATE TABLE orders (
  id INT PRIMARY KEY,
  amount NUMERIC CHECK (1 = 1)
);

Compliant Solution

CREATE TABLE orders (
  id INT PRIMARY KEY,
  amount NUMERIC CHECK (amount > 0)
);
