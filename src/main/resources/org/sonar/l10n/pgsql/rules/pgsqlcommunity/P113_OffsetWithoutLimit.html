Why is this an issue?

An OFFSET clause without a corresponding LIMIT still requires PostgreSQL to compute and discard every skipped row before returning the rest of the result set. This wastes I/O and CPU and often indicates a missing pagination bound.

Noncompliant Code Example

SELECT id, name FROM users ORDER BY id OFFSET 100;

Compliant Solution

SELECT id, name FROM users ORDER BY id LIMIT 20 OFFSET 100;
