Using procedural CURSOR in PostgreSQL is generally less efficient than set-based operations.

  • Performance: Cursors process rows one at a time, avoiding query optimizer benefits
  • Complexity: Code becomes harder to maintain and understand
  • Resource Usage: Cursors consume more memory and locks

Recommendation: Use set-based operations (JOINs, window functions, CTEs) whenever possible.

Noncompliant Code:

DECLARE user_cursor CURSOR FOR SELECT * FROM users;
OPEN user_cursor;
FETCH NEXT FROM user_cursor INTO @user_id;

Compliant Code:

SELECT id, name FROM users;
-- Use set-based operations or language-level iteration
