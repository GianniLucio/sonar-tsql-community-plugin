Every table should define a PRIMARY KEY to ensure data integrity and enable efficient queries.

  • Data Integrity: PRIMARY KEY prevents duplicate or NULL rows
  • Performance: Automatically creates an index for faster lookups
  • Relationships: Required for foreign key constraints
  • Best Practice: Industry standard database design

Recommendation: Define a PRIMARY KEY for every table.

Noncompliant Code:

CREATE TABLE users (
  id INT,
  name VARCHAR(100),
  email VARCHAR(100)
);

Compliant Code:

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100)
);
-- Or using GENERATED:
CREATE TABLE users (
  id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100)
);
