CHECK constraints should not compare a value with NULL using = or <>.

In three-valued SQL logic, any comparison with NULL using = or <> evaluates to UNKNOWN, never to FALSE. Oracle accepts UNKNOWN as satisfying a CHECK constraint, so the constraint silently never rejects rows on that condition. Use IS NULL or IS NOT NULL instead.

Noncompliant Code Example

CREATE TABLE employees (
    id NUMBER PRIMARY KEY,
    status VARCHAR2(20) CHECK (status = NULL)
);

Compliant Solution

CREATE TABLE employees (
    id NUMBER PRIMARY KEY,
    status VARCHAR2(20) NOT NULL
);
