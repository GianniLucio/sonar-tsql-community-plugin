Anonymous PL/SQL blocks should define an EXCEPTION handling section.

An anonymous DECLARE/BEGIN ... END block, such as those used in migration and deployment scripts, has no caller-provided error handling. Without an EXCEPTION block, any runtime error aborts the script with no opportunity to log context or perform cleanup.

Noncompliant Code Example

BEGIN
    UPDATE accounts SET balance = balance - 100 WHERE account_id = 1;
END;
/

Compliant Solution

BEGIN
    UPDATE accounts SET balance = balance - 100 WHERE account_id = 1;
EXCEPTION
    WHEN OTHERS THEN
        RAISE;
END;
/
