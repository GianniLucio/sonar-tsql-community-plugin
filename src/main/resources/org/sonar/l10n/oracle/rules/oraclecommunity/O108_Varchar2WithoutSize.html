Why is this an issue?

Declaring a VARCHAR2 column without an explicit size relies on an implementation-defined or session-dependent default. This can silently truncate data, behaves inconsistently across environments, and hides the intended maximum length from anyone reading the schema.

Noncompliant Code Example

CREATE TABLE employees (
  id NUMBER PRIMARY KEY,
  name VARCHAR2
);

Compliant Solution

CREATE TABLE employees (
  id NUMBER PRIMARY KEY,
  name VARCHAR2(100)
);
