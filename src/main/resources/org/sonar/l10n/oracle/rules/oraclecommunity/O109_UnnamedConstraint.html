Table constraints should be explicitly named.

An unnamed constraint receives a system-generated name (e.g. SYS_C0012345) that gives no indication of its purpose and makes it harder to identify in error messages, scripts, or when altering/dropping the constraint later.

Noncompliant Code Example

CREATE TABLE employees (
    id NUMBER,
    PRIMARY KEY (id)
);

Compliant Solution

CREATE TABLE employees (
    id NUMBER,
    CONSTRAINT pk_employees PRIMARY KEY (id)
);
