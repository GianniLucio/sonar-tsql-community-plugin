Why is this an issue?

The PRINT statement sends messages through the tabular data stream, which client drivers may buffer, ignore, or discard. It is not a reliable channel for diagnostics, auditing, or error handling, and application code cannot easily capture it.

Noncompliant Code Example

PRINT 'Processing started';

Compliant Solution

-- Use a logging table, extended events, or return the information via THROW/RAISERROR
INSERT INTO dbo.ProcessLog (Message, LoggedAt) VALUES ('Processing started', GETUTCDATE());
