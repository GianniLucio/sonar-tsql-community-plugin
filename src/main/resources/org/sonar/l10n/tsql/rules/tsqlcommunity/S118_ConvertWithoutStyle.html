CONVERT to a date/time data type should specify an explicit style code.

When the third, optional style argument of CONVERT is omitted, SQL Server falls back to a default style that depends on the connection's language and regional settings. The same code can therefore produce different results (or fail) depending on where and how it runs.

Noncompliant Code Example

SELECT CONVERT(DATETIME, @rawValue);

Compliant Solution

SELECT CONVERT(DATETIME, @rawValue, 120); -- ODBC canonical style, unambiguous
