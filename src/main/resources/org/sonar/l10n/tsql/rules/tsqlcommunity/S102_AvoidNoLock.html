Why is this an issue?

The NOLOCK or READUNCOMMITTED table hints instruct SQL Server to read uncommitted transactions:

  • Causes dirty reads, reading values that are subsequently rolled back.
  • Causes phantom reads and skipping or duplicating rows during index page splits.
  • May cause query failures with Error 601 (data movement error).

Noncompliant Code Example

SELECT OrderID, TotalAmount FROM dbo.Orders WITH (NOLOCK) WHERE Status = 'Shipped';

Compliant Solution

Prefer using Read Committed Snapshot Isolation (RCSI) or Snapshot Isolation at database level, or omit the hint:

SELECT OrderID, TotalAmount FROM dbo.Orders WHERE Status = 'Shipped';
