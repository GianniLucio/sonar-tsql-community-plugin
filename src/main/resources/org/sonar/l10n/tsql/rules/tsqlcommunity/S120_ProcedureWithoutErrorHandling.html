Stored procedures should handle errors with a BEGIN TRY ... END TRY / BEGIN CATCH ... END CATCH block.

Without structured error handling, an unexpected runtime error aborts the batch and can leave the caller without any diagnostic information, and any open transaction may be left in an inconsistent state.

Noncompliant Code Example

CREATE PROCEDURE dbo.usp_UpdateBalance AS
    UPDATE dbo.Accounts SET Balance = Balance - 100 WHERE AccountId = 1;

Compliant Solution

CREATE PROCEDURE dbo.usp_UpdateBalance AS
BEGIN TRY
    UPDATE dbo.Accounts SET Balance = Balance - 100 WHERE AccountId = 1;
END TRY
BEGIN CATCH
    THROW;
END CATCH;
