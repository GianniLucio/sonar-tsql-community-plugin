Why is this an issue?

Using SELECT * or SELECT table.* queries in production code, views, and stored procedures causes significant issues:

  • Retrieves unnecessary columns across the network, wasting database and I/O bandwidth.
  • Prevents query optimizer from using covering non-clustered indexes.
  • Breaks application mapping when columns are added, removed, or reordered in underlying tables.

Noncompliant Code Example

SELECT * FROM dbo.Customers WHERE Status = 1;

Compliant Solution

SELECT CustomerID, CustomerName, Email FROM dbo.Customers WHERE Status = 1;
