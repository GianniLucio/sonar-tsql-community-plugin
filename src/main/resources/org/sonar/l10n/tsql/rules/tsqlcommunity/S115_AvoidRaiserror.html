Why is this an issue?

RAISERROR has quirky formatting rules, does not preserve the original error's line number or procedure context reliably, and cannot be used to simply rethrow a caught error. THROW, introduced in SQL Server 2012, is simpler and rethrows the original exception when used without arguments inside a CATCH block.

Noncompliant Code Example

RAISERROR('Invalid order total', 16, 1);

Compliant Solution

THROW 51000, 'Invalid order total', 1;
