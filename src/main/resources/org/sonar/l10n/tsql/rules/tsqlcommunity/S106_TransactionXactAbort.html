Why is this an issue?

In T-SQL, by default when a runtime statement error occurs inside an explicit transaction (BEGIN TRANSACTION), SQL Server does not automatically roll back the entire transaction unless SET XACT_ABORT ON is specified or a structured exception block (TRY...CATCH) rolls it back.

This frequently causes orphaned open transactions, connection pool deadlocks, and blocking chains.

Noncompliant Code Example

BEGIN TRANSACTION;
UPDATE dbo.Accounts SET Balance = Balance - 100 WHERE AccountID = 1;
UPDATE dbo.Accounts SET Balance = Balance + 100 WHERE AccountID = 2;
COMMIT TRANSACTION;

Compliant Solution

SET XACT_ABORT ON;
BEGIN TRANSACTION;
UPDATE dbo.Accounts SET Balance = Balance - 100 WHERE AccountID = 1;
UPDATE dbo.Accounts SET Balance = Balance + 100 WHERE AccountID = 2;
COMMIT TRANSACTION;
