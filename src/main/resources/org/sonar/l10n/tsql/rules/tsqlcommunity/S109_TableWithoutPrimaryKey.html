Why is this an issue?

In relational database design, every table should have a PRIMARY KEY constraint to uniquely identify each row and ensure physical storage clustering or index optimization.

Noncompliant Code Example

CREATE TABLE dbo.AuditLogs (
    LogID INT,
    Message NVARCHAR(500),
    CreatedAt DATETIME
);

Compliant Solution

CREATE TABLE dbo.AuditLogs (
    LogID INT IDENTITY(1,1) PRIMARY KEY,
    Message NVARCHAR(500),
    CreatedAt DATETIME NOT NULL
);
